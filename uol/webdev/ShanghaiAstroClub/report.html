Coursework Report

Introduction:

As a child in Canada I was intrigued by the stars and astronomy, but it was a solitary pleasure. It was not until much later in life that I joined an astronomy club and discovered the joy that comes from being with other people who share the same passion. I now live in Shanghai, one of the largest cities on the planet. This website envisions a group of people who overcome tall buildings and light pollution in pursuit of this noble celestial hobby.

I chose a very simple, open and welcoming structure for my site design. Cartoon graphics, clean fonts, large white spaces and direct jargon-free language are intended to make the club approchable to new and potential members. At the same time, the site endeavors to provide uncluttered access to information that serious club members need at their fingertips such as geographical coordinates, moon phases, and sun rise/set times.

Inspiration:

The members of my astronomy club back in Canada came from all walks of life, all ages, all levels of education and all income brackets. Their hobby brought them together and disolved diferences in a way that I found amazing and truly inspiring. This observation influenced how I determined the target audience of this website.

I find astronomers in general foster a worldwide culture of generosity and sharing. The vast majority of astronomical tools and information on the internet is produced by amature astronomers. I am inspired by this sharing of time and information and the Shanghai Astronomy Club website endeavors to reflect that.

Above all I am inspired by our creator. I truly believe the beauty and wonder of our universe is his gift to mankind and that part of his purpose is for us to find joy and accomplishment in discovering its treasures.

Accessibility:

Three ways in which accessabily has been considered.

  • (Perceivable) Image alt atribute: All images have alt text defined allowing screen readers to access a description of the image. Images that are for decoration contain a null value for alt text to notify screen readers that these images can be safely ignored.
  • (Operable) Tab order: All interactive elements on the page are logically ordered top down and left to right. This allows intuitive keyboard-only accessabily to all interactive elements.
  • (Understandable) Heading hierarchy: This site strictly adheres to the hierarchy of heading tags. This order is important to the use of screen readers, search engines, etc. to give logical semantic structure to the page irrespective of styling.

Usability:

Three ways in which usability has been considered.

  • Consistant Design: All pages are designed with exactly the same header, navigation bar and footer. This gives the user a consistant point of reference regardless of where he is on the site.
  • Standard Design Conventions: The site is designed to conform with conventional website designs (ie. Logo and nav bar at top, underlined hyperlinks, contact information in footer, etc.). This give the user an intuitive sense of how to accomplish the tasks he wishes to perform based on his cumulative experience visiting other websites.
  • Link states: Hover states and pointer changes are used consistantly on all user interactive elements. This serves as a visible indication to the user that the element can be interacted with without having to provide specific instructions. Visited links also change colour giving the user a visual indication of where he has already been.

Learning:

I have virtually no experience with HTML, CSS and only very little experience with JavaScript programming. So virtually every aspect of creating this website was a learning opportunity. While coding this site I made extensive use of the video lectures and my personal notes from this course. I found following the same steps used when creating our midterm group project emmensely helpful. By first creating a wireframe followed by HTML then CSS and finally JavaScript I found I was able to break the project into small tasks and work thru them one at a time.

While coding the HTML I made extensive use of W3Schools.com HTML reference pages. I quickly learned the purpose of the various tags, but it took time to learn the various attributes and syntax for each tag.

Coding the CSS was more challenging. Here I again used W3Schools.com but I found the step by step CSS Tutorials more helpful than the Reference section. The code examples were rarely useful for my application but I was able to follow the methodology and apply the techniques to my own site. I found positional formating the most difficult. I needed to learn relative vs absolute positioning, flexbox, and grid layout more thoroughly.

Coding JavaScript that interacted with the DOM was definitly the most challenging part of the project for me. My initial design called for more coding than I was capable of. I found most online tutorials and code examples started above my level and assumed I knew more than I did about JavaScript syntax and manipulating the DOM. I found that a better approach was to simplify my design and focus on creating my own JavaScript from scratch using the knowledge I had gained in ITP1. I used MDN Web Docs at mozilla.org as a reference to implement the JavaScript commands I needed.

Evaluation I:

What aspect(s) worked well and why?

I am pleased with the overall design of the site. I think the footer is particularly attractive and responds well to diferent device widths. I am impressed with how small styling changes like 0.3 second transitions applied to the hover state really make the website feel polished and professional.

I feel the JavaScript interactions that provide the information for the Sky Events information worked very well. I was very happy to find Astronomy Library for JavaScript by Don Cross which provided the astronomical formulas which allowed me to calculate the sun and moon rise times and moon phases locally rather than pulling the information from an external server. I feel the changing moon phase image is also well implemented.

My favorite is the Sky Chart page. The page is dominated by a beautiful all-sky representation customized for an observer in Shanghai at that exact moment and changes slowly as objects move across the sky. I was very pleased to find VirtualSky provided freely for educational and non-profit use by Las Cumbres Observatory.

Evaluation II:

What aspect(s) could be improved, and how?

My initial concept called for club events and sky events to be manipulated with sorting and filters and then pushed to the DOM using JavaScript. I understand the general concept, but I was unable implement this functionality. Idealy I would like the source data to be in a separate data file which would allow a client to easily make additions and changes without having to deal with HTML or JavaScript coding, perhaps in a CSV file that could be edited by the end user in Excel.

I planned to implement a "night mode" commonly used by astronomers while observing to protect their night vision. Implementation would require removing all blue and white light sources from the website. Making changes to text is easy, however the challenge of manipulating colours on dozens of icons and photos caused me to abandon this idea. A way this could be implemented would be to create an entire second set of images meets the red light requirements. A better way would be to use some sort of transfom to manipulate images on the fly.

I thought it would be a good idea to use JavaScript to copy frequently repeated HTML snippets (ie. header, footer, nav bar) into the HTML rather than repeating the same HTML over and over agian on each page. My implementation worked fairly well, but it also introduced a few unexpected problems that I spent many hours trying to troubleshoot. It seems that HTML code inserted using innerHTML can not be selected by JavaScript for other DOM manipulations. According to some conversations I read on stackoverflow.com the replaceChild() method may have been more appropriate for this application.

While I attempted to create a responsive design that would respond well to device viewport sizes, I did not create scaled images and video that would be more considerate of a user's mobile bandwidth. I feel this is an important aspect of responsive design that should not be ignored. Given more time I would certainly attempt to implement this functionality.

I really dislike when a page jumps around as it loads content. I would like to study ways to deal with this problem in the future.
